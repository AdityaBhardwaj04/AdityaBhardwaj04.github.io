# BLACKBOX Content Architecture

Version 1.0

Author: Aditya Bhardwaj

---

# Purpose

This document defines every piece of written content used throughout BLACKBOX.

Its purpose is to ensure consistency.

Every heading.

Every button.

Every loading message.

Every empty state.

Every terminal response.

Every tooltip.

Every notification.

Should sound like it belongs to the same product.

---

# Brand Voice

BLACKBOX speaks like professional software.

Not marketing.

Not social media.

Not a resume.

The tone should be

Professional

Calm

Technical

Minimal

Confident

Helpful

Never arrogant.

Never dramatic.

---

# Writing Principles

Short sentences.

Clear language.

No unnecessary adjectives.

No buzzwords.

No fluff.

Every sentence should provide information.

---

# Things Never To Say

Passionate

Highly Motivated

Results Driven

Rockstar

Ninja

Guru

World Class

Expert In Everything

Cutting Edge

Disruptive

Innovative

Game Changing

---

# Preferred Language

Instead of

"I'm passionate about cybersecurity."

Use

"I work on application security, vulnerability assessment and security automation."

---

Instead of

"I love solving problems."

Use

"I build tools that reduce repetitive security work."

---

Instead of

"I have excellent teamwork."

Use

"Worked with development teams to validate security fixes."

---

Show.

Don't advertise.

# Writing Rules

Never exceed

20 words

for UI labels.

Never exceed

100 words

for summaries.

Avoid paragraphs longer than four lines.

Prefer lists where appropriate.

---

# Grammar Rules

Sentence case.

Not Title Case.

Use active voice.

Avoid unnecessary punctuation.

No emojis inside the application.

No excessive exclamation marks.

One exclamation mark maximum.

---

# Future Content

Every future module should follow the same writing principles.

Consistency is more important than creativity.

---

# Final Principle

Every piece of text should answer one question:

**"Would this sound natural inside a premium enterprise security product?"**

If the answer is **no**, rewrite it.

End of Document.
